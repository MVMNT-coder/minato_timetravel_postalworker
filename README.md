# 時空郵便局 — 2045年の誰かの日常を、ちょっと変える

2026年と2045年を郵便でつなぐ「時空郵便局」。来場者は「食べる・着る・住む」の3つの未来から1つを選び、そこで暮らす人から届いた手紙を読んで、身の回りの物を1つ撮影して送ります。物を受け取った未来人から返信が届き、その人の日常が「変わった」「ちょっと変わった」「変わらなかった」のどれかになります。最後に、現代の「当たり前」と未来の価値観のギャップを1文で見せ、詳しいレポートは左のサブディスプレイに届きます。

世界観は「SFプロトタイピング簡易体験ツール 世界観設定書（v4）」の衣・食・住の3本です。

## 体験の流れ（16画面・約2分20秒）

ボタンを押すのは「はじめる」「未来を選ぶ」「撮影して送る」の3回。ほかの画面は声が終わると自動で進みます（下の段の「次へ」の線が残り時間。押せばすぐ進む）。声が流れているあいだはボタンを受け付けません（押しすぎて手紙を読み飛ばさないように）。

## セットアップ

### 1. Claude API キーを用意する
1. [Claude Console](https://console.anthropic.com) で API キーを発行します。
2. 使いすぎを防ぐため、Console の「Limits」で月の利用上限を設定しておきます。

### 2. スプレッドシートと GAS を作る
1. Google スプレッドシートを新規作成します（名前は自由）。
2. メニューの「拡張機能 > Apps Script」を開きます。
3. `コード.gs` の中身を全部消し、このリポジトリの `gas/Code.gs` を貼り付けて保存します。
4. 左メニューの「プロジェクトの設定（歯車）」の一番下にある「スクリプト プロパティ」に、次を追加します。

| プロパティ | 値 | 必須 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 発行した API キー | ○ |
| `MODEL` | 使うモデル（既定 `claude-sonnet-5-5`） | |
| `RATE_PER_MIN` | 1分あたりの受付上限（既定 `30`） | |
| `SAVE_IMAGES` | `false` にすると写真を保存しない | |
| `GEMINI_API_KEY` | Google AI Studio で発行した Gemini の API キー。同封の写真（想像図）を Gemini で描くときに使う | |
| `GEMINI_IMAGE_MODEL` | Gemini の画像モデルの既定（既定 `gemini-nano-banana-2.1`）。ふだんはスタッフ用パネルで選ぶ | |

**想像図のAIの切り替え**：ページで Ctrl+Shift+S を押してスタッフ用パネルを開き、「想像図」で、Claude（線画）／Gemini（画像）／描かない を選びます。Gemini を選ぶと、送った物の写真も参考に渡して描かせます（速さを優先するなら Gemini）。「Geminiでテスト」で、キーが使えるかを確かめられます。設定はそのPCのブラウザに保存されます。Gemini の画像は、ドライブの `minato_images` フォルダに保存し、シートの「想像図」列にURLを残します。

**AIへの依頼は3つ**：撮影した瞬間に「返信と判定」を頼み（約10〜15秒。転送と「返事を待つ」の画面で待ち時間を隠す）、それが届いた瞬間に「想像図」と「詳しいレポート」を裏で頼みます。想像図とレポートは待たずに先へ進み、届きしだい左の画面に出ます。別のPCの左の画面には、シートの「想像図（小）」「レポート」列から届きます。

5. エディタ上部の関数選択で `setupCheck` を選んで「実行」します。許可の画面が出るので、自分のアカウントで許可します。シートに `log` タブと動作確認の行ができれば成功です（確認の行は消してかまいません）。

### 3. ウェブアプリとして公開する
1. 右上の「デプロイ > 新しいデプロイ」を開き、種類に「ウェブアプリ」を選びます。
2. 次画面で次のように設定して、デプロイします。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
3. 表示された URL（`https://script.google.com/macros/s/…/exec`）をコピーします。ブラウザで開いて `{"ok":true,…,"ready":true}` と出ればOKです。

> `Code.gs` を書き換えたときは、「デプロイを管理」から既存のデプロイを編集し、バージョンを「新バージョン」にして更新します。URL は変わりません。

### 4. ページに URL を設定して公開する
1. `config.js` の `window.GAS_URL = "";` の `""` の中に、手順3でコピーした URL を貼って commit します。
2. GitHub のリポジトリで「Settings > Pages」を開き、Source を「Deploy from a branch」、Branch を `main` / `(root)` にして保存します。
3. 数分後に `https://mvmnt-coder.github.io/minato_timetravel_postalworker/` で開けます。

## 運用メモ
- **費用**：撮影1回につき Claude API を1回呼びます。費用はキーを発行したアカウントに請求されます。
- **連打対策**：GAS 側で1分あたりの受付数を制限しています（`RATE_PER_MIN`）。
- **写真の保存**：来場者の写真がドライブに残ります。画面にも「保存されます」と表示しています。不要なら `SAVE_IMAGES` を `false` にしてください。
- **GAS の上限**：無料の Google アカウントでは外部通信が1日2万回まで、同時実行は30件程度までです。展示の規模なら通常は足ります。
- **プロンプトの調整**：AIへの指示は `gas/Code.gs` の `PROMPT_MISSION`（返信と判定。XMLタグで階層に分けた指示）と `PROMPT_REPORT`（詳しいレポート）、未来ごとの情報は `FUTURES` にあります。`FUTURES` には、世界の概要・この世界の当たり前・差出人のプロフィール・手紙・お願い・お手本（3段階）・現在の兆し（出典つきの固定の文）を書いていて、`buildMissionPrompt_` が指示に差し込みます。AIは点数を「お願いに応えたか（30）・未来の常識とぶつかるか（40）・未来人が動いたか（30）」の内訳で出し、合計はGASで計算し直します。写真からわからない味や手ざわりは、AIが創作で補ってよいことにしています。判断の途中経過はシートの「判定メモ」列に残ります。`FUTURES` は `src/js/stories.js` の `FUTURES` と同じ順番にそろえてください。
- **集計のリセット**：`mission_log_v5` シートの2行目以降を消すと、待機画面の配達数が0に戻ります。

## GASの自動デプロイ（GitHub Actions）

`gas/` の中を変更して `main` に push すると、GitHub Actions が Apps Script のコードを更新し、既存のウェブアプリを新バージョンでデプロイし直します。ウェブアプリのURLは変わりません。Actions タブの「Deploy GAS」から手動で実行することもできます。

最初に一度だけ、次の設定が必要です。

1. **Apps Script API をオンにする**：<https://script.google.com/home/usersettings> を開き、「Google Apps Script API」をオンにします。
2. **clasp でログインする**：Mac のターミナルで次を実行し、開いたブラウザで GAS を作った Google アカウントを許可します。
   ```
   npx @google/clasp@2.4.2 login
   ```
   ログインできたら、次のコマンドで認証情報を表示してコピーします。
   ```
   cat ~/.clasprc.json
   ```
3. **ID を2つ控える**
   - スクリプトID：Apps Script エディタの「プロジェクトの設定（歯車）」→「スクリプト ID」
   - デプロイID：「デプロイ > デプロイを管理」→ 今使っているウェブアプリの「デプロイ ID」
4. **GitHub に Secrets を登録する**：リポジトリの「Settings > Secrets and variables > Actions > New repository secret」で、次の3つを登録します。

| Name | 値 |
|---|---|
| `CLASPRC_JSON` | 手順2でコピーした `~/.clasprc.json` の中身すべて |
| `GAS_SCRIPT_ID` | スクリプトID |
| `GAS_DEPLOYMENT_ID` | デプロイID |

> `CLASPRC_JSON` は、あなたの Google アカウントで Apps Script を操作できる鍵です。チャットや Issue などには貼らず、GitHub の Secrets にだけ登録してください。

設定が済んだら、Actions タブの「Deploy GAS」→「Run workflow」で一度実行し、緑のチェックが付けば完了です。以後は `gas/` を push するたびに自動で反映されます。

- 自動デプロイでは、`gas/appsscript.json` の設定（実行ユーザー：自分、アクセス：全員）が使われます。
- Apps Script 側で直接コードを書き換えても、次の自動デプロイで GitHub の内容に上書きされます。

## 展示モード（USBカメラ＋物理ボタン1つ＋2画面）

展示用PCでは、URLの末尾に `?exhibit=1` を付けて開きます（一度開くとそのブラウザに記憶されます。解除は `?exhibit=0`）。

- **物理ボタン**：Enter / Space（テンキーのEnterも可）を1つのボタンとして扱います。押す必要があるときは、画面左下にオレンジのボタン（「ボタンを押して、はじめる」「ボタンを押して、この未来にする」「ボタンを押して、撮影して送る」）が出ます。
  - ほかの画面は、声が終わって少し待つと自動で次へ進みます（左下の「次へ」の線が残り時間。押すとすぐ進む）。声が流れているあいだと転送中は、押しても何も起きません。
  - 連打（0.8秒以内）と長押しの連続入力は無視します。処理中は入力を受け付けません。
- **USBカメラ**：内蔵カメラより外部カメラを優先して使います。展示モードではカメラを開いたままにして、毎回の起動待ちをなくしています。
- **スタッフ用パネル**：`Ctrl + Shift + S` で開閉します。カメラの選択とプレビュー、物理ボタンのキー登録（ボタンが Enter/Space 以外のキーを送る場合）、テスト音、声、想像図のAI、同封の写真を表示する時間（既定7秒）、TOPへの強制リセットができます。
- **自動リセット**：撮影の画面は、操作がないまま60秒たつと待機画面に戻ります（戻る10秒前から残り秒数が出ます）。ほかの画面は自動で進み、最後の「あなたの当たり前」から待機画面に戻ります。
- マウス操作もそのまま使えます（画面のボタンをクリックしても同じ動作になります）。

### 2画面（メインと、左の配達レポート）

同じWindowsのPCに2台のディスプレイをつなぎ、メインに体験、左に配達レポートを出します。

1. HDMIとDisplayPort（DVIも可）で1台ずつつなぎ、Windowsの「設定 > ディスプレイ」で「表示画面を拡張する」を選びます。並びは実際の配置どおり、サブを左にします。
2. `start-exhibit.bat` をダブルクリックすると、同じChromeで2つのウィンドウが開きます（サブの位置は中の `SUB_X` で合わせる）。思った画面に出ないときは、ウィンドウを選んで Windows + Shift + ← / → で移し、F11 で全画面にします。
3. 2つのウィンドウは同じChromeのプロフィールで開いてください。プロフィールを分けると、カードが左へ飛ぶ演出とレポートが同期しません。
4. 別々のPCで動かすこともできます。その場合、左の画面はシートを5秒ごとに確かめ、届いたものから出します（演出とは少しずれます）。

### 演出ありモード（外周の演出）

URLの末尾に `?fx=1` を付けて開くと、展示モードに加えて「演出ありモード」になります（解除は `?fx=0`。スタッフ用パネルからも切り替えできます）。

- アプリの画面を中央に少し縮めて表示し、外側の余白（既定は上下左右それぞれ5%、合計で縦横の1割）を演出に使います。プロジェクターでスクリーンからはみ出した部分が、そのまま演出になる想定です。
- 余白の幅は、スタッフ用パネルの「外周の幅（片側）」で 3〜15% に変えられます。「演出を順番にテスト」で、全部の演出を5秒ずつ確認できます。

| 場面 | 外周の演出 |
|---|---|
| 待機 | 光が外周をゆっくり回る |
| ミナト・未来を選ぶ・手紙・返信 | 通信の波形 |
| カメラ | 走査する白い光と四隅の枠 |
| 時空転送 | 光の筋が画面から外へ噴き出す（だんだん激しくなる） |
| 返事を待つ・同封の写真 | 鼓動のような明滅 |
| 変わった | 白と金のやわらかい光、舞い上がる光の粒 |
| ちょっと変わった | 光がつきかけて、ちらつきながら消える |
| 変わらなかった | 赤い点滅（1秒に1回）のあと、灰が降る |

## ミナトと差出人の声（VOICEVOX）

ミナトのセリフ、手紙、お願い、返信を、音声で読み上げます。読み方の追加は `src/js/audio.js` の `READ` で行います。

1. 展示用PCに [VOICEVOX](https://voicevox.hiroshiba.jp/) をインストールして起動します（起動している間だけ声が出ます）。
2. VOICEVOX の「設定 > オプション」などからエンジンの設定を開き、**CORS Policy Mode を `all`** にして再起動します（ブラウザで `http://127.0.0.1:50021/setting` を開いても設定できます）。
3. Chrome でページを開いたとき、「ローカル ネットワーク上のデバイスへのアクセス」の許可を求められたら「許可」します。
4. スタッフ用パネル（`Ctrl + Shift + S`）の「ミナトの声」で、接続状態の確認、声（キャラクター）の選択、テスト再生、音量の調整ができます。
5. 手紙・お願い・返信は、差出人の声で読み上げます。同じ欄の「手紙の差出人の声（未来ごと）」で、ミノリ・ツムギ・ソラの声をそれぞれ選べます（既定：玄野武宏、冥鳴ひまり、ずんだもん）。

- VOICEVOX が起動していない、または接続できないときは、ブラウザ内蔵の読み上げで代用します。
- VOICEVOX の音声を公開の場で使うときは、選んだキャラクターの利用規約に従い、クレジット（例：`VOICEVOX:四国めたん`）を表示してください。待機画面の下に自動で表示しています。

## 未来の線画と、同封の写真

- **未来の線画**：3つの未来それぞれの線画（社食、リペア工房、スクリーンの部屋）を `src/js/art.js` の `WORLD_ART` に入れています。手紙が届く画面で1本ずつ描かれます。
- **画像への差し替え**：`WORLD_IMG` の同じ位置に画像のパスを書くと（例：`["img/world1.png","",""]`）、その未来は線画の代わりに画像を表示します。画像は 4:3 を想定しています。
- **同封の写真**：返信と判定が届いた瞬間に、AIの考えた場面（`ill_scene`）をもとに想像図を描かせます。返信を読んでいるあいだに届けば「同封の写真」の画面で出し、間に合わなければ未来の線画を出して、想像図はあとで左の画面に届けます。

## 体験の設定

- **表の設定**：2026年と2045年を郵便でつなぐ時空郵便局。2045年の「食べる・着る・住む」の未来で暮らす人から手紙が届き、来場者は物を1つ送る。未来人は自分の世界をおおむね普通で快適だと感じていて、その暮らしの中に、現代から見ると少し不思議な習慣や価値観がある。
- **ねらい**：身近な物を未来へ送ることで、未来の誰かの暮らしに小さな変化が起き、その反応を通して自分たちが当たり前だと思っている価値観に気づく。
- **結果**：75点以上「◯◯の日常が、変わった」、50〜74点「ちょっと変わった」、49点以下「変わらなかった」。客観的な評価ではなく、ゲームとしての判定。
- **現在の兆し**：レポートの「この未来は、もう始まっているかもしれません」は、AIに書かせず、`FUTURES` に出典ごと固定で入れた文を出します。公開前に出典と照合してください。

## 左の画面（配達レポート）

- **開き方**：URLの末尾に `?view=archive` を付けて、左のサブディスプレイに全画面で表示します（`start-exhibit.bat` で自動）。カメラや音は使いません。メイン画面からは `G` キーで開閉します。
- **画面**：左に同封の写真（想像図）と送った物、右にレポート。レポートは3ページを自動でめくります（受け取った人・返信の全文・総評／ギャップの核心・比較表／揺らいだ瞬間・現在の兆し・あなたへの問い）。届いたときに判定の印が押されます。右上は全期間の人数です。
- **新着**：メインの最後の画面でカードが左へ飛ぶと、同じタイミングで右端から入ってきます。新着がないあいだは、過去のレポートを順に流します。
- 表示するのは新しい60件までです。記録はスプレッドシートの `mission_log_v5` から読み込みます。
